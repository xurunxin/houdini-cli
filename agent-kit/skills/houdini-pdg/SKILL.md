# houdini-pdg

## 激活与依赖
TOP/PDG变体、作业依赖、缓存和交付；不并行抢占同一个GUI桥接。
必须同目录安装 `houdini-agent`。先遵循 [执行协议](../houdini-agent/wiki/02-cli-contract.md)，不替代原有 `houdini-cli` 的环境和生命周期能力。

## 开始前
确认目标、已有节点路径、Houdini版本、输入数据、输出格式及允许修改范围。只有阻塞安全执行的信息才询问；其余列明假设并从低成本原型开始。

## 按需知识
- [按需阅读：PDG / TOPs：批量任务、变体与依赖](../houdini-agent/wiki/26-pdg.md)
- [按需阅读：缓存、导入导出、路径与交付](../houdini-agent/wiki/27-cache-io.md)

## 工作顺序
1. 用 `houdini-agent/tools/query.py search` 检索当前问题，只读取命中卡片；读取现场工具schema和节点参数。
2. 检查领域输入：输入清单、work item属性、依赖、输出文件命名、scheduler、许可证/内存/设备并发预算。
3. 写清数据流和修改计划。先独立完成一个work item，然后扩展wedge。每个变体的输出包含任务/资产/版本/seed，防止路径冲突。
4. 在用户授权范围或任务命名空间做最小试验，串行调用；不重置全场景，不覆盖无关节点。
5. 每阶段检查真实数据再继续。仅可重复且状态已知的任务允许调度重试。CLI超时未知的GUI写操作不属于安全自动重试对象。
6. 提交证据，记录失败/未验证项，结束会话时默认保留应用。

## 必须验收
- 每个item的输入、属性、输出和日志可追踪。
- 一个item失败不会覆盖其他变体的输出。
- 小批次通过后才提高并发，许可证与内存有现场验证。

## 失败与降级
- 输出互相覆盖：路径缺少wedge/item/版本字段。
- 看起来成功但拿到旧缓存：核对输入指纹和cache命中依据。
工具缺失时先确认 schema；专用能力不存在才考虑经检查的 HOM。`guide` 或 `discovery` 文档均不代表现场已经通过运行验收。超时先查状态，不重复提交未知写操作。

## 交付
输出：目标与假设、实际版本、网络/参数改动、缓存/渲染/导出路径、技术与视觉验收证据、未验证项及下一步检查。不得用本地Python语法测试冒充Houdini运行测试。
